# v0.4 科学评测方案（一页版）

> 制定：GLM（受用户委托直接实施）｜日期：2026-11-12
> 对应规划 §6 v0.4 七项确认，逐项如下。**本方案与实现同步生效；数据未接入前，评测输出一律为「未评测」。**

## 1. 科学问题

**cartesian_ddg 常规模式预测的单点突变稳定性变化 ΔΔG（REU），与实验测得的稳定性变化 ΔΔG（kcal/mol）在趋势上是否一致（秩相关/线性相关）。** 仅此一个问题。结合亲和力（SKEMPI/PDBbind）**不是**本任务的科学问题——旧流水线中的那两个对照保持"默认关闭、探索性"不变，不进入本评测。

## 2. 数据来源（任务匹配的稳定性基准）

- **候选**：ProThermDB（prothermdb.org）、ThermoMutDB、及文献整理集 S669 / Ssym（引用见下）。
  - Pancotti et al., *Brief Bioinform* 2019（S669/Ssym 整理集）
  - ThermoMutDB: Xavier et al., *NAR* 2021
- **接入规则**（与 `docs/data_provenance.md` 同一政策）：数据文件**不随仓库分发**；接入时记录来源、版本、下载日期、许可、数据字典，填入该文档。
- **当前状态：未接入。** 在用户提供/确认具体来源前，评测工具输出「未评测」——这是诚实默认，不是缺失。

## 3. 数据匹配（链感知，修复 P0-D 的同类问题）

样本 key = **(pdb_id, chain, resnum_pdb, wt_aa1, mut_aa1)** ——五元组，**链必须一致**；同编号不同链不得合并（旧流水线 SKEMPI 的链无关匹配教训）。排除规则（逐条记录原因）：
- 插入码位点：排除（v0.2 CLI 本就拒绝执行）
- 基准表 wt 与我们结构实测 wt 不一致：排除（编号体系疑异，宁缺毋错）
- 同 key 多条测量（不同条件）：**取均值并记录条数**（透明处理，不静默）
- 基准缺 exp_ddg 列/非法值：排除
- 我们这侧无对应 run 或 result 非成功：排除

## 4. 输出量与单位

预测 = ΔΔG (REU)；实验 = ΔΔG (kcal/mol)。**不换算单位**（REU 无公认换算系数）；相关性是尺度无关的，因此只解读"趋势方向与相对大小"，报告里同时给出两列原始值供人工核对。方向约定：两者均以 >0 为去稳定化。

## 5. 指标

- **n < 20（默认，可调）**：不计算任何相关系数，输出匹配表 + `样本不足，不计算指标`。
- **n ≥ 20**：Pearson r、Spearman ρ、MAE（标注"跨单位，仅作相对参考"）。
- **不输出任何"强/中/弱可信度"或"评测通过"字样**——只报数值与 n，解释留给研究者。

## 6. 基线

第一版**无基线**（如实声明"首次评测，基线协议待定"）。后续候选：以"预测恒为样本均值"的零模型做相关基线、或复现已发表的 cartesian_ddG 基准数字（需先确认其 protocol 与我们一致）。

## 7. 不确定性

- 每份评测附机器可读明细 `eval_details.json`（每个样本的匹配/排除及原因、数据集哈希）。
- 声明：单结构参考态、constant_seed 单次采样、无重复；**计算筛选 ≠ 实验验证**。
- 不相关数据集（如误传 SKEMPI CSV）会因 schema 校验失败而**整体拒绝评测**——结构上杜绝"跑通即通过"。

## 交付物

- CLI：`python -m workbench.evaluate --benchmark <csv> --runs runs/...`（可多次运行聚合）
- 每次评测：`runs/eval_<时间>/` 下 `eval_details.json`（机器可读）+ `report.txt`（人可读）
- 数据缺失 → 报告明示「未评测」并给出接入步骤
