#### 实时日志流式输出

`submit_task` 是生成器函数（用 `yield`）：

```python
def submit_task(protein_file, ligand_file, mutation_mode, mutation, params, user_msg, history, error_box, current_task_state):
    # ... 前置处理
    yield history, "", error_box, task_id  # 立即返回初始状态

    for event in agent_executor.stream(...):
        for node_name, node_state in event.items():
            # ... 根据消息类型追加日志
            yield history, "", error_box, task_id  # 流式更新 Gradio
```

每次 `yield` 都更新 Gradio 的 Chatbot 组件，实现**实时滚动日志**。

### 1.2 CLI 单跑模式

```bash
python rosetta_agent.py --mode cli \
    --protein complex.pdb \
    --mutation 76,73 \
    --params "并发数 4, 延迟 3" \
    --msg "请跑这两个位点的饱和突变"
```

参数说明：

| 参数 | 必填 | 说明 |
|---|---|---|
| `--mode` | 否 | `web`（默认）/ `cli` |
| `--protein` | 是（cli） | 蛋白文件路径 |
| `--ligand` | 否 | 配体文件路径（不传则 PyMOL 自动分离） |
| `--mutation` | 是（cli） | 突变位点（逗号分隔） |
| `--params` | 否 | 额外参数（如并发数） |
| `--msg` | 否 | 附加自然语言指令 |

### 1.3 CLI 批量模式

`run_cli.sh` 循环遍历 `inputs/pdbs/*.pdb`：

```bash
for pdb in inputs/pdbs/*.pdb; do
    python rosetta_agent.py --mode cli \
```

## 2. 安装与环境

| 依赖 | 版本要求 | 用途 |

## 3. 运行流程详解

### 3.1 首次运行流程

```bash
# 1. 克隆项目
git clone https://github.com/clearlove-seven1/rosetta-agent-pipeline.git
cd rosetta-agent-pipeline

# 2. 创建环境
conda env create -f environment.yml
conda activate rosetta-agent

# 3. 配置环境变量
cp .env.example .env
nano .env  # 填入 LLM KEY 和 Rosetta 路径

# 4. （可选）安装 ESM-2
pip install fair-esm torch --index-url https://download.pytorch.org/whl/cpu

# 5. 启动 Web 界面
python rosetta_agent.py
```

浏览器开 `http://<server-ip>:7777`。

### 3.2 任务提交流程（Web）

1. 上传 `protein.pdb`（必需）
2. 上传 `ligand.pdb/mol2`（可选，不传则自动从复合物分离）
3. 选择"单位点突变"或"多位点批量"
4. 填突变位点（如 `76` 或 `71,72,A_23`）
5. 填其他参数（如 `并发数 10, 延迟 1.5`）
6. 可选：填附加指令（如 `请跑完所有位点的饱和突变`）
7. 点"提交执行"

后台开始跑：
1. PyMOL 分离配体（如需）
2. 参数化 → 弛豫 → disorder → 突变扫描
3. 后台轮询进度
4. SKEMPI/PDBbind 评估
5. 总结输出

用户在 Chatbot 看到实时日志。等收到"✅ 后台计算全部完成"，点"刷新并打包下载结果"，得到 `.zip`。

### 3.3 任务提交流程（CLI）

```bash
# 单跑
python rosetta_agent.py --mode cli \
    --protein complex.pdb \
    --mutation 76,73 \
    --params "并发数 4, 延迟 3"

# 批量（用 run_cli.sh）
mkdir -p inputs/pdbs
cp target1.pdb target2.pdb inputs/pdbs/
bash run_cli.sh
```

### 3.4 任务目录结构

每次任务创建独立目录：

```
output/
└── task_20260913_1500_1abc/
    ├── protein.pdb                    # 复制的输入
    ├── ligand.pdb                     # 自动分离或用户上传
    ├── parameterize_ligand/           # Step 1 产物
    │   ├── LIG.params                 # Rosetta 拓扑文件
    │   ├── LIG.pdb                    # 配体 PDB
    │   └── LIG_0001.pdb               # 配体构象
    ├── cartesian_relax/               # Step 2 产物
    │   ├── wt_relaxed.pdb             # 弛豫后的复合物
    │   ├── score.sc                   # 能量分数
    │   └── *.log                      # 运行日志
    ├── saturation_mutagenesis/        # Step 3 产物
    │   ├── S1_76A.ddg                  # 每个突变体的 ΔΔG
    │   ├── S1_76A.pdb                  # 突变体结构
    │   ├── run_launcher.log
    │   └── rosetta_tasks.txt          # 突变任务列表
    ├── disorder/
    │   └── disorder_scores.csv        # ESM-2 全量 disorder 分数
    └── summary/
        ├── ddg_results.txt            # 汇总的 ΔΔG 表
        └── binding_eval_report.txt    # SKEMPI/PDBbind 对照报告
```

## 6. 排错指南

| 现象 | 排查方向 |
|---|---|
| `.ddg` 文件 0 字节 | 看 `saturation_mutagenesis/run_launcher.log`，多半并发过大打挂 Rosetta |
| 弛豫中途 `score.sc` 写不出来 | `cartesian_relax/` 下 `score_*.sc` 是不是 3 个都在 |
| 报"找不到 .params" | 确认 `parameterize_ligand/` 里有 `.params` 落盘 + 目录权限 |
| SKEMPI 报"未找到 PDB XXX" | 该 PDB 不在 SKEMPI 收录范围（SKEMPI 只有蛋白-蛋白相互作用） |
| SKEMPI 报"位点重叠 0" | `ddg_results.txt` 里的 key 格式与 SKEMPI 突变解析对不上（链不参与匹配） |
| ESM-2 报"fair_esm 未安装" | 跑 `pip install fair-esm torch`，或接受 B-factor 启发式回退 |
| Gradio 启动失败 | 检查 7777 端口是否被占用 |
| LLM 一直报"工具不可用" | 检查 `bind_tools` 调用是否正确 |
| 任务卡在 progress_poll | 30 分钟超时，可手动 fetch 看部分结果 |

## 8. 安全注意事项

1. **API KEY 不要硬编码**在代码里，用 `.env` 文件
2. **`.env` 已加入 `.gitignore`**，不会被推到 GitHub
3. **不要在公网裸跑 Web 服务**（无身份认证），用 Nginx + 防火墙
4. **敏感 PDB / 结果文件**考虑加密存储
5. **HPC 服务器**用 VPN/堡垒机访问，不要暴露 7777 到公网
