# 01 · 项目背景与目标

## 1.1 蛋白设计与 Rosetta 的工程痛点

蛋白设计（Protein Design）是合成生物学与药物研发的核心环节：给定一个目标蛋白（如酶、抗体），通过**突变其氨基酸序列**来改变其性质（结合力、稳定性、催化活性等）。Rosetta 是该领域事实标准的开源软件包，由华盛顿大学 Baker 实验室开发，提供从结构预测到能量评估再到突变扫描的全套工具链。

但 Rosetta 的使用门槛极高：

1. **命令行驱动**：所有功能（配体参数化、弛豫、ΔΔG 计算）都是 C++ 编译的二进制，靠 shell 脚本串起来
2. **参数冗杂**：每个工具几十上百个 flag，新手难以上手
3. **失败不友好**：报错信息是 C++ 抛出的 stack trace，没有 LLM 帮你诊断
4. **并发配置复杂**：饱和突变扫描是 n×19 次独立任务（n 个位点 × 19 个氨基酸），CPU/IO 调度全靠用户写 shell
5. **可信度评估难**：算出来的 ΔΔG 是不是准？需要回查 SKEMPI / PDBbind 实验数据库做相关性分析——这一步 99% 的用户都跳过

## 1.2 项目的核心目标

把上述 5 个痛点一次性解决：

| 痛点 | 本项目解法 |
|---|---|
| 命令行门槛 | 自然语言驱动（上传 PDB + 写一句指令即可） |
| 参数冗杂 | LangGraph 图拓扑 + schema 物理约束（LLM 只能调对应工具） |
| 失败不友好 | 专用 `repair` 分支 + `diagnose_and_fix` / `auto_repair` 工具 |
| 并发复杂 | ThreadPoolExecutor 自动并发 + 错峰扫描 |
| 可信度盲区 | 自动接 SKEMPI / PDBbind 算 Pearson/Spearman |

**一句话目标**：让一个不懂 Rosetta 的生物学家，也能跑完整套饱和突变 ΔΔG 扫描并自动拿到可信度报告。

## 1.3 为什么需要 LLM Agent

乍一看，这事儿不就是写个 Python 脚本把 Rosetta 命令串起来吗？为什么要套个 LangGraph Agent？

**核心论点：传统脚本 vs Agent 架构**

| 维度 | 传统 shell 脚本 | LangGraph Agent |
|---|---|---|
| 执行顺序 | 写死在代码里 | 图边 + schema 状态机约束 |
| 工具权限 | 无（任何工具都能调） | 每节点 `bind_tools` 物理限制 |
| 错误恢复 | 写 `if error then ...` | 专用 repair 分支 |
| 用户交互 | 写死参数 / 改代码 | 自然语言 + 上下文 |
| 可信度评估 | 通常跳过 | 自动接实验数据库 |

**关键洞察**：把"顺序、权限、错误恢复"这些**控制流职责**从 prompt 文字下沉到图结构里，LLM 只负责**意图理解**——这是本项目最重要的架构决策。

## 1.4 项目的差异化定位

市面上已有工具：

- **RosettaScripts / PyRosetta**：纯代码库，没 UI 也没自动恢复
- **Rosetta Online Server**：Web 界面，但只支持单步操作，没法批量突变
- **ProteinMPNN / RFdiffusion**：AI 蛋白设计，但不算 ΔΔG
- **LangChain / LangGraph 通用 Agent**：技术栈对，但没和具体科学计算结合

本项目的独特价值：**把 LLM Agent 范式落到具体领域（蛋白设计）的全栈实现**——从底层工具封装、图拓扑设计、并发调度，到实验数据库对照，全部跑通。

## 1.5 典型应用场景

1. **抗体亲和力成熟**：拿到抗原-抗体复合物晶体结构，跑饱和突变找高亲和力变体
2. **酶活性改造**：对活性位点残基做饱和扫描，定向提高 kcat/Km
3. **蛋白-蛋白相互作用优化**：找关键界面残基的"hot spot"
4. **耐热性改造**：通过 ΔΔG 预测找稳定性提高的突变
5. **药物耐受性突变预警**：预测病原体关键蛋白突变对药物结合的影响

## 1.6 项目成果指标

- **覆盖度**：跑完一个蛋白-配体复合物的饱和突变 + 实验对照，端到端**零人工**
- **性能**：单蛋白饱和突变交付周期从"天级"压缩到"小时级"（768 核 HPC）
- **可靠性**：单步失败自动 repair 重试，最大 2 次
- **可解释**：每个 ΔΔG 数值都能追溯到具体的 Rosetta 计算任务与实验对照

## 1.7 限制与未来工作

诚实地说，本项目目前：

1. **不是生产级**：科研原型，适合内部使用
2. **依赖 Rosetta 编译环境**：需要在服务器上装好 Rosetta 全套
3. **ESM-2 可选**：没装 fair-esm 时回退到 B-factor 启发式，精度降低
4. **可信度评估依赖数据库收录**：SKEMPI 只有蛋白-蛋白相互作用，PDBbind 只有蛋白-小分子

未来可扩展方向：
- 接入 Boltz / AlphaFold3 做突变体结构预测
- 接入更多 Rosetta 应用（酶设计、protein-protein docking）
- 加可视化报告（PyMOL 自动标 hot residue）
