# 03 · 蛋白设计工具集

蛋白设计（Protein Design）是 Rosetta 的**核心强项**——给定 backbone 三维结构，找到能量最低的氨基酸序列。本章详细介绍所有设计相关工具。

## 1. 蛋白设计总览

### 1.1 三种设计模式

| 模式 | 含义 | 难度 | 工具 |
|---|---|---|---|
| **Fixed-backbone design** | 固定 backbone，只换序列 | 简单 | fixbb |
| **Backbone design** | 自由 backbone + 序列 | 难 | CoupledMoves |
| **De novo design** | 从头设计骨架+序列 | 极难 | SEWING / RFdiffusion+Rosetta |

### 1.2 设计的基本方程

```
min_{sequence} E_total(sequence, fixed_backbone)
```

**关键约束**：
- 主链 backbone 二面角要在合理范围（Ramachandran）
- 侧链 rotamer 空间有限
- 整体疏水核心、亲水表面的"油水分配"
- 几何可实现性（不能原子重叠）

## 2. Fixed-backbone Design（固定骨架设计）

### 2.1 fixbb（基础工具）

**命令**：`fixbb.linuxgccrelease`

**最常用的设计工具**，固定 backbone 优化侧链：

```bash
fixbb.linuxgccrelease \
    -s input.pdb \
    -resfile design_residues.resfile \
    -nstruct 10 \
    -score:weights ref2015.wts
```

**resfile（设计约束文件）**：

```
NATRO                  # 所有残基：保持原样（默认）
NATAA                  # 保持原氨基酸，但优化 rotamer
PIKAA ST               # 位点 1: 允许 S、T
ALLAA                  # 位点 2: 允许所有 20 种氨基酸
PIKAA FILVWYAM         # 位点 3: 允许疏水 + AlaMet
EMPTY                  # 空行
START                  # 开始标记
```

**resfile 类型**：

| 关键字 | 含义 |
|---|---|
| `NATRO` | 保持原样，不优化 |
| `NATAA` | 保持原氨基酸，只换 rotamer |
| `NATRO` + `ALLAA` | 混合使用 |
| `PIKAA <list>` | 指定可突变氨基酸 |
| `PIKAA ST` | 只允许 Ser / Thr |
| `ALLAA` | 允许全部 20 种 |
| `ALLAAxc` | 全部但不包括 Cys |
| `EMPTY` / `END` | 段结束 |

### 2.2 FastDesign（快速设计协议）

**FastDesign = FastRelax + design 交替**，比 fixbb 更优：

```bash
fixbb.linuxgccrelease \
    -s input.pdb \
    -fixbb \
    -relax:default_repeats 5 \
    -nstruct 10
```

**算法**：

```
循环 5 次:
    MutateResidue（按 resfile 试探新序列）
    FastRelax（侧链 + backbone 微调）
    蒙特卡洛接受/拒绝
```

### 2.3 LayerDesign（分层设计）

**Rosetta 经典设计原则**：蛋白应该**核心疏水 / 表面亲水 / 边界两亲**。

**LayerDesign** 显式施加这一约束：

```bash
fixbb.linuxgccrelease \
    -s input.pdb \
    -layer_design \
    -resfile layers.resfile
```

**分层规则**：

| 层 | 位置 | 偏好氨基酸 |
|---|---|---|
| **核心** | 全埋藏残基 | L, I, V, F, M, A, W |
| **边界** | 部分暴露 | A, L, I, V, F, M, Q, E, K, R |
| **表面** | 全部暴露 | D, E, K, R, N, Q, S, T, Y, H, G |

### 2.4 OptE / OptH（优化）

**OptE**（Optimize Energies）：多目标 Pareto 优化

**OptH**（Optimize Hydrogen）：极性氢位置优化

### 2.5 CoupledMoves（协同设计）

**核心思想**：backbone + 序列**同时**变化。

```bash
coupled_moves.linuxgccrelease \
    -s input.pdb \
    -nstruct 100 \
    -mc_kt 1.0 \
    -boltzmann_chi
```

**适用场景**：loop 区域设计、de novo 折叠。

### 2.6 Sequence Profile（序列谱设计）

用同源序列比对（MSA）作约束：

```bash
fixbb.linuxgccrelease \
    -s input.pdb \
    -resfile design_with_profile.resfile \
    -aa_profile profile.txt \
    -pssm_mode true
```

**profile.txt** 格式：

```
position:  1   2   3   4   5   ...
A:        0.1 0.0 0.8 0.2 ...
C:        0.0 0.0 0.0 0.0 ...
D:        0.0 0.0 0.0 0.5 ...
...
```

**适用**：保守位点保持原氨基酸，可变位点放开设计。

## 3. 酶设计（Enzyme Design）

### 3.1 enzdes（酶设计协议）

酶设计 = **活性位点 + 底物 + 催化残基**三位一体设计。

```bash
enzdes.linuxgccrelease \
    -s input.pdb \
    -extra_res_fa ligand.params \
    -resfile cst_resfile \
    -cstfile constraints.cst \
    -nstruct 1000
```

**关键概念**：

- **Theozyme**（理论酶）：理想化的活性位点几何
- **化学约束文件**（.cst）：定义反应过渡态
- **口袋设计**：在蛋白中挖出容纳底物的口袋

### 3.2 经典成果

**Diels-Alder 合成酶**（2010，Science）：

- 用 Rosetta 从头设计 Diels-Alder 反应的催化酶
- 2012 年通过实验验证
- 2014 年提升活性 ~100 倍

### 3.3 现代酶设计工具

| 工具 | 用途 |
|---|---|
| `enzdes` | 经典酶设计 |
| `OZ`（Ozyme） | 酶优化框架 |
| `Kemp_elim` | Kemp 消除反应专用 |
| `retro_aldol` | 逆羟醛反应专用 |
| `MATCH` | 蛋白-小分子匹配 |

## 4. 抗体设计（Antibody）

### 4.1 RosettaAntibody

抗体结构 = **抗原识别 + 框架区**：

- 框架区（Framework）：相对保守
- CDRs（互补决定区）：高变，决定特异性

**抗体建模任务**：

1. **同源建模**：给定序列预测三维结构
2. **抗体-抗原对接**：建模结合模式
3. **抗体亲和力成熟**：优化 CDR 序列

```bash
antibody.linuxgccrelease \
    -s input.pdb \
    -mode H3 \
    -nstruct 100
```

**H3 loop**（CDR-H3）是抗体最关键的 loop，长度变异最大（8-20 残基），建模难度最高。

### 4.2 SnugDock

**抗体-抗原柔性对接**协议：

```bash
snugdock.linuxgccrelease \
    -s antibody_antigen.pdb \
    -nstruct 1000
```

**核心**：CDR loop 柔性 + 抗原刚性平移/旋转。

### 4.3 抗体应用

- 治疗性抗体（Herceptin、Humira 等）
- 抗体人源化（降低免疫原性）
- 双特异性抗体
- 抗体药物偶联（ADC）

## 5. SEWING 与片段拼接

### 5.1 SEWING（Structure Extension With Native-substructure Graphs）

**SEWING** = **De novo 蛋白骨架生成**，通过拼接已有片段：

```bash
sewing.linuxgccrelease \
    -s input.pdb \
    -nstruct 1000 \
    -motif_accepted
```

**核心思想**：

1. 从 PDB 库提取所有螺旋/折叠片段
2. 在 N-/C- 端坐标匹配片段
3. 拼接形成新骨架
4. 用 Rosetta 设计序列

### 5.2 legacy_sewing / SEWING-v2

更新版本，支持更灵活的拼接。

### 5.3 fold_from_loops

从 Loop 出发构建整个蛋白：

```bash
fold_from_loops.linuxgccrelease \
    -loops loops.txt \
    -frag3 frags.3mers \
    -frag9 frags.9mers
```

## 6. Membrane Protein Design（膜蛋白设计）

### 6.1 RosettaMembrane

膜蛋白 = 跨膜区 + 膜外区 + 膜内区，能量函数特殊。

**MPer**（Membrane Protein Energy）：专门处理脂双层。

```bash
mpframework.linuxgccrelease \
    -s membrane_protein.pdb \
    -mp:lipids:composition DLPC \
    -nstruct 100
```

### 6.2 mp_dock

膜蛋白-蛋白对接：

```bash
mp_dock.linuxgccrelease \
    -s receptor.pdb ligand.pdb \
    -mp:setup:spanfiles receptor.span ligand.span
```

## 7. 现代 ML 融合工具

### 7.1 ProteinMPNN（序列设计）

**ProteinMPNN** 是 ML 时代的序列设计器，**比 Rosetta 快且准**：

```bash
# 用 ProteinMPNN 生成序列
python protein_mpnn_run.py \
    --pdb_path input.pdb \
    --out_folder output/ \
    --num_seq_per_target 10
```

**与 Rosetta 配合**：

1. ProteinMPNN 生成候选序列
2. Rosetta FastRelax 优化结构
3. Rosetta cartesian_ddg 评估 ΔΔG

### 7.2 RFdiffusion（De novo 设计）

**RFdiffusion** 基于 RF（RoseTTAFold）架构生成全新蛋白骨架：

```bash
# 见 RFdiffusion 仓库
python run_inference.py \
    --config-module configs/inpaint.yml \
    --input.pdb input.pdb \
    --output.prefix output/design
```

**与 Rosetta 配合**：

1. RFdiffusion 生成骨架
2. ProteinMPNN 生成序列
3. Rosetta FastRelax 优化
4. **Rosetta 评估 ΔΔG 是物理验证关键步骤**

### 7.3 Chroma（Generate Biomedicines）

**Chroma** 是 Generate Biomedicines 的蛋白设计平台，结合 ML + 物理约束。

### 7.4 FrameDiff / Genie / 等

其他 de novo 设计工具，处于早期发展阶段。

## 8. 设计的实际工作流

### 8.1 单点突变（最简单）

```bash
# 1. 准备 PDB
# 2. 写 resfile
# 3. 跑 fixbb
fixbb.linuxgccrelease -s input.pdb -resfile m.resfile -nstruct 1

# 4. 评估能量
extract_pdbs.linuxgccrelease -in:file:silent out.silent
```

### 8.2 多点突变（ΔΔG 扫描）

```bash
# 1. 跑 cartesian_ddg（本项目用）
cartesian_ddg.linuxgccrelease \
    -s wt.pdb \
    -ddg:mut_file mutations.txt \
    -ddg:iterations 3 \
    -score:weights ref2015_cart.wts \
    -nstruct 1

# 2. 解析 ddg_results.txt
```

### 8.3 全 de novo 蛋白设计

```bash
# 1. 用 RFdiffusion 生成骨架
python run_inference.py --config-module configs/design.yml

# 2. 用 ProteinMPNN 生成候选序列
python protein_mpnn_run.py

# 3. 用 Rosetta 评估 + 优化
fixbb.linuxgccrelease
fastrelax.linuxgccrelease
cartesian_ddg.linuxgccrelease

# 4. 实验验证
```

### 8.4 抗体亲和力成熟

```bash
# 1. 抓取 CDR 序列
# 2. 模拟突变
fixbb.linuxgccrelease -resfile cdr.resfile

# 3. 评估结合
interface_ddg.linuxgccrelease

# 4. 排序 top hits
```

## 9. 设计的常见评估指标

### 9.1 能量

```bash
# 全局能量
extract_pdbs.linuxgccscore.linuxgccrelease

# 逐残基能量
per_residue_energies.linuxgccrelease
```

### 9.2 几何合理性

| 检查 | 工具 |
|---|---|
| 键长键角 | `molprobity` |
| Ramachandran | `rampage` |
| 原子冲突 | `Rosetta clash_score` |
| 旋转异构体 | `molprobity_rotamer` |

### 9.3 实验对照

- **表达量**：在大肠杆菌中表达
- **溶解度**：SEC / 光散射
- **热稳定性**：DSF / DSC（Tm）
- **结合活性**：SPR / ITC / BLI
- **酶活性**：动力学参数（kcat、Km）

### 9.4 计算对照

- **ProteinMPNN score**：ML 分数
- **AlphaFold 复算结构**
- **MD 稳定性模拟**

## 10. 蛋白设计的局限性（诚实声明）

### 10.1 当前做不到的

1. **完美酶活性设计**：高活性（kcat > 100）极难
2. **真 de novo 多肽**：< 30 残基的超小蛋白仍困难
3. **膜蛋白设计**：跨膜区精度差
4. **蛋白-蛋白相互作用设计**：高亲和力 + 高特异性双优难
5. **翻译后修饰**：糖基化、磷酸化难直接设计

### 10.2 计算成本

| 任务 | 单次时间 | 典型任务数 |
|---|---|---|
| fixbb 单点序列扫描 | 10 分钟 | 10-100 |
| 19 氨基酸饱和扫描 | 5 小时 | 1-10 |
| 全 de novo 蛋白 | 48 小时 | 100-1000 |

### 10.3 实验差距

**Rosetta 计算 ΔΔG 与实验 ΔΔG 的相关性**：典型 Pearson r = 0.5-0.7。

→ **计算排名 ≠ 实验排名**，必须做湿实验验证。

## 11. 一句话总结

**Rosetta 的蛋白设计工具集覆盖了从单点突变（fixbb）到 de novo 全新蛋白设计（SEWING / RFdiffusion+Rosetta）的完整光谱，是当前蛋白工程领域不可替代的核心工具——尤其在 ΔΔG 评估、物理验证、与实验数据库对照等 ML 工具薄弱的环节。**
