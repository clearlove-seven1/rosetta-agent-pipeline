# 07 · 本项目使用的 Rosetta 工具详解

本章详细拆解本项目（rosetta-agent）的三段式流水线**直接调用**的 3 个 Rosetta 工具，是整个项目的科学计算核心。

## 1. 三段式流水线回顾

```
┌────────────────────────────────────────┐
│  Step 1: parameterize_ligand           │  → molfile_to_params.py
├────────────────────────────────────────┤
│  Step 2: run_cartesian_relax           │  → relax.linuxgccrelease -relax:cartesian
├────────────────────────────────────────┤
│  Step 3: run_saturation_mutagenesis    │  → cartesian_ddg.linuxgccrelease
└────────────────────────────────────────┘
```

**这三个工具分别负责**：

| 工具 | 任务 | Rosetta 命令 |
|---|---|---|
| `molfile_to_params.py` | 配体参数化 | Python 脚本（非二进制） |
| `relax.linuxgccrelease` | 结构弛豫 | `relax.linuxgccrelease -relax:cartesian -score:weights ref2015_cart` |
| `cartesian_ddg.linuxgccrelease` | 饱和突变 ΔΔG | `cartesian_ddg.linuxgccrelease -ddg:mut_file mutations.txt` |

## 2. molfile_to_params.py 详解

### 2.1 工具定位

| 项目 | 内容 |
|---|---|
| **类型** | Python 脚本（不是二进制） |
| **位置** | `$ROSETTA_TOOLS/molfile_to_params.py` |
| **作者** | Rosetta 团队 |
| **用途** | 把非标准残基（配体）转换为 Rosetta 可识别的 `.params` 拓扑文件 |
| **最新版** | 跟随 Rosetta 主线更新 |

### 2.2 为什么需要它

Rosetta 默认只认识 **20 种标准氨基酸**（ALA、GLY、...）。**配体（ligand）是非标准残基**——小分子有机物、金属离子、共价修饰等。

要 Rosetta 处理配体，必须：

1. 给配体定义**原子类型**（如 C、H、O、N、S、P、卤素）
2. 定义**键合**（哪些原子成键）
3. 定义**电离态**（如羧基去质子化）
4. 定义**内部坐标**（ideal coordinates）

`.params` 文件就是这些信息的载体。

### 2.3 输入与输出

**输入**：
- `ligand.pdb` 或 `ligand.mol2`（包含原子坐标）
- 可选：`.mol2`（包含键合信息，比 PDB 详细）

**输出**：
- `LIG.params`：参数文件（残基定义）
- `LIG_0001.pdb`：配体 PDB（带 ideal coordinates）
- 可选：`LIG.conformers.pdb`：多构象

### 2.4 命令详解

```bash
$ROSETTA_TOOLS/molfile_to_params.py \
    --name LIG \                    # 3 字符残基代号（必须大写）
    --pdb ligand.pdb \              # 输入 PDB
    --mol2 ligand.mol2 \            # 可选：mol2 格式（推荐）
    --out-dir params/ \             # 输出目录
    --extra-properties               # 输出额外属性
```

**关键参数**：

| 参数 | 含义 |
|---|---|
| `--name` | **3 字符残基代号**，必须大写、唯一 |
| `--pdb` | 输入 PDB 路径 |
| `--mol2` | 可选，推荐 |
| `--out-dir` | 输出目录 |
| `--clobber` | 覆盖已有文件 |
| `--keep-names` | 保留原始原子名（用于 rmsd 计算） |
| `--extra-properties` | 输出额外属性 |
| `--longest-chain-as-ligand` | 多链时取最长链为配体 |

### 2.5 3 字符代号选择

**3 字符代号是配体的身份证**，必须：

- 3 个大写字母
- 不与 20 种氨基酸冲突（不要用 `ALA`、`GLY` 等）
- 不与现有配体代号冲突

**自动检测**：本项目用启发式——选 CONECT 记录中原子最多的几个原子对中**最短的 3 字母组合**。

### 2.6 .params 文件结构

```params
NAME LIG                                      # 残基名
IO_STRING LIG X                                # IO 单字符表示（X = 杂）
TYPE LIGAND                                    # 类型：LIGAND
AA UNK                                         # 氨基酸枚举：未知
FORMULA C20H25N3O2                             # 化学式（可选）

# 原子定义（每个原子一行）
ATOM  C1   C    X   -1.000   0.000   1.000   0.000   0.000  -0.001   0.000
ATOM  C2   C    X   -1.000   0.000   1.000   0.000   0.000  -0.001   0.000
...（所有原子）

# 键合
BOND  C1   C2
BOND  C2   C3
...（所有键）

# 链终止（virtual atom）
CONNECT  C1   CUT  CUT_DUMMY_ATOM
```

### 2.7 在本项目中的调用

代码位置：[rosetta_tools.py 第 169-232 行](../../详解rosetta-agent/04-核心代码详解.md)

```python
@tool
def parameterize_ligand(ligand_path: str = "ligand.pdb") -> str:
    """调 molfile_to_params.py 配体参数化"""
    try:
        # 1. 检测 ROSETTA_BIN 在 PATH
        rosetta_tools = os.getenv("ROSETTA_SCRIPTS_DIR")

        # 2. 解析 ligand_path 是 .pdb 还是 .mol2
        is_mol2 = ligand_path.endswith(".mol2")

        # 3. 提取 3 字符代号（启发式）
        three_letter_code = _extract_ligand_code(ligand_path)

        # 4. 调 molfile_to_params.py
        cmd = f"{rosetta_tools}/molfile_to_params.py \
            --name {three_letter_code} \
            --pdb {ligand_path}"
        if is_mol2:
            cmd = cmd.replace("--pdb", "--mol2")

        result = subprocess.run(cmd, shell=True, capture_output=True, text=True)

        if result.returncode != 0:
            return f"【执行报错】molfile_to_params.py 退出码 {result.returncode}：\n{result.stderr}"

        # 5. 检查 .params 是否生成
        params_file = os.path.join(workspace, f"{three_letter_code}.params")
        if not os.path.exists(params_file):
            return f"【执行报错】{params_file} 未生成"

        return f"✅ 配体参数化成功：{params_file}"

    except Exception as e:
        return f"【系统异常】配体参数化失败：{e}"
```

### 2.8 常见错误

| 错误 | 原因 | 解决 |
|---|---|---|
| `ERROR: Cannot find CONECT records` | PDB 缺 CONECT | 用 `obabel` 等工具补 CONECT |
| `ERROR: Atom type unknown` | 原子类型 Rosetta 不识别 | 检查 PDB 元素列是否正确 |
| `ERROR: Bond too long` | 键长异常 | 检查 PDB 坐标 |
| `ERROR: Residue name X already exists` | 代号冲突 | 改名 |

### 2.9 配体前处理建议

```bash
# 1. 用 OpenBabel 优化配体 3D 坐标
obabel ligand.smi -O ligand_3d.sdf --gen3d

# 2. 转 mol2
obabel ligand_3d.sdf -O ligand.mol2

# 3. 加氢（pH 7.4）
obabel ligand.mol2 -O ligand_h.mol2 -p 7.4

# 4. 检查键合
obabel ligand_h.mol2 -O ligand_h.mol2 -xC
```

## 3. relax.linuxgccrelease 详解

### 3.1 工具定位

| 项目 | 内容 |
|---|---|
| **类型** | C++ 编译二进制 |
| **位置** | `$ROSETTA_BIN/relax.linuxgccrelease` |
| **用途** | 结构弛豫优化 |
| **核心算法** | FastRelax（蒙特卡洛 + 模拟退火 + 能量最小化） |
| **本项目用法** | `relax.linuxgccrelease -relax:cartesian -score:weights ref2015_cart` |

### 3.2 弛豫（Relaxation）是什么

**Relax** = 优化一个 PDB 结构的能量，使其更接近"自然稳定态"。

**应用**：

1. **实验结构预处理**：X-ray / Cryo-EM 结构常有几何冲突，弛豫去冲突
2. **对接后精修**：对接生成的初始结构粗糙，需要精修
3. **突变后优化**：突变残基可能产生冲突，需要局部弛豫
4. **MD 后处理**：MD 模拟后的结构弛豫回"平衡态"

**原理**：用 Rosetta 的能量函数（ref2015_cart）评估结构，做蒙特拉罗/模拟退火优化。

### 3.3 FastRelax 协议

**FastRelax** 是 Rosetta 的标准弛豫协议：

```cpp
// FastRelax 算法（伪代码）
Pose pose = read_input_pdb(input);

ScoreFunction sf = ref2015_cart;

// 5 次循环：
for (int repeat = 0; repeat < 5; ++repeat) {
    // 1. 全原子 CartRelax（Cartesian 最小化）
    MinMover().apply(pose);

    // 2. RotamerTrialsMover（侧链 rotamer 优化）
    RotamerTrialsMover(sf).apply(pose);

    // 3. Monte Carlo 接受/拒绝
    mc.boltzmann(pose);
}

// 4. 最终能量最小化
MinMover().apply(pose);
```

**关键设计**：

- **Cartesian 空间弛豫**（本项目）：直接调原子坐标
- **Torsional 空间弛豫**：调二面角
- **模拟退火**：温度从高到低（kT 1.0 → 0.1）

### 3.4 在本项目中的命令

```bash
relax.linuxgccrelease \
    -s complex.pdb \                      # 输入 PDB
    -relax:cartesian \                    # Cartesian 弛豫
    -relax:default_repeats 5 \            # FastRelax 重复次数
    -score:weights ref2015_cart.wts \     # 能量函数
    -nstruct 3 \                          # 生成 3 个独立结构
    -out:prefix S1_ \                     # 输出文件前缀
    -extra_res_fa LIG.params              # 配体参数文件
```

**关键参数**：

| 参数 | 含义 |
|---|---|
| `-s` | 输入 PDB（复合物） |
| `-relax:cartesian` | **Cartesian 空间弛豫**（不用 torsional） |
| `-relax:default_repeats 5` | FastRelax 循环次数（默认 5） |
| `-score:weights ref2015_cart.wts` | 能量函数 |
| `-nstruct 3` | **3 路独立弛豫**（取最低能量） |
| `-extra_res_fa LIG.params` | 配体拓扑 |
| `-out:prefix S1_` | 输出文件前缀 |
| `-out:file:silent relax.silent` | silent 输出（可选） |
| `-out:file:scorefile relax.sc` | 能量文件 |

### 3.5 输出文件

| 文件 | 内容 |
|---|---|
| `S1_0001.pdb` | 弛豫后结构（nstruct 个） |
| `S1_0001.fasta` | 对应序列 |
| `score.sc` | 能量报告 |
| `*.log` | 运行日志 |

**score.sc 格式**：

```
SEQUENCE: SCORE: total_score     fa_atr     fa_rep     ...   description
SCORE:    -1234.567       -456.789     123.456    ...   S1_0001
SCORE:    -1230.123       -450.123     130.123    ...   S1_0002
SCORE:    -1225.456       -445.123     135.123    ...   S1_0003
```

**最优结构** = 能量最低的（最后一个）。

### 3.6 Cartesian vs Torsional 弛豫

| 维度 | Cartesian | Torsional |
|---|---|---|
| 修改对象 | 原子坐标 | 二面角（φ/ψ/χ） |
| Speed | 慢 ~ 2x | 快 |
| Loop 友好度 | 好 | 中 |
| Helix 友好度 | 中 | 好 |
| 本项目选择 | **是**（用于弛豫） | - |

**Cartesian 弛豫的优势**：直接调坐标能修复原子级冲突，特别适合从对接或 MD 来的初始结构。

### 3.7 在本项目中的并发实现

代码位置：[rosetta_tools.py run_cartesian_relax](../../详解rosetta-agent/04-核心代码详解.md)

```python
@tool
def run_cartesian_relax(protein_pdb: str = "protein.pdb", nstruct: int = 3) -> str:
    """3 路并发跑 relax.linuxgccrelease"""
    workspace = get_workspace_path("cartesian_relax")

    # 1. 复制输入 PDB 到工作区
    target_pdb = os.path.join(workspace, "complex.pdb")
    if not os.path.exists(target_pdb):
        shutil.copy(protein_pdb, target_pdb)

    # 2. 找 LIG.params（来自 Step 1）
    params_files = glob.glob(f"{workspace}/../parameterize_ligand/*.params")

    # 3. 写脚本（含 ThreadPoolExecutor）
    script = f"""
import subprocess, os
from concurrent.futures import ThreadPoolExecutor

rosetta_bin = "{os.getenv('ROSETTA_BIN_DIR')}/relax.linuxgccrelease"
score_weights = "{rosetta_tools}/scores/ref2015_cart.wts"

def execute(i):
    cmd = f"{rosetta_bin} \\
        -s complex.pdb \\
        -relax:cartesian \\
        -score:weights {{score_weights}} \\
        -nstruct 1 \\
        -out:prefix S{{i}}_ \\
        {extra_res_str}"
    return subprocess.run(cmd, shell=True, capture_output=True)

with ThreadPoolExecutor(max_workers={nstruct}) as pool:
    for i in range(1, {nstruct} + 1):
        pool.submit(execute, i)
"""
    # 4. 写脚本到工作区并执行
    script_path = os.path.join(workspace, "run_relax.py")
    with open(script_path, "w") as f:
        f.write(script)

    result = subprocess.run(["python", script_path], capture_output=True, text=True)

    # 5. 等待 score.sc 完整生成
    while True:
        score_files = glob.glob(f"{workspace}/score_*.sc")
        if len(score_files) >= nstruct:
            break
        time.sleep(5)

    # 6. 选能量最低的作为 wt_relaxed.pdb
    min_score_pdb = _select_lowest_energy(workspace)

    return f"✅ Cartesian 弛豫完成，最优能量 = {min_score} REU"
```

### 3.8 常见问题与调优

| 问题 | 原因 | 解决 |
|---|---|---|
| `score.sc` 写不出来 | IO 阻塞 | 加 `-out:file:scorefile` 单独写 |
| 弛豫后结构变差 | nstruct 不够 | 增加到 5-10 |
| 配体跑出结合口袋 | 弛豫过度 | 用 constraints 限制 |
| 内存不够 | 蛋白太大 | 拆分 domain 弛豫 |

### 3.9 弛豫的局限

⚠️ **Cartesian 弛豫不是万能的**：

1. 不能修复**大尺度错误**（如错误折叠）
2. 只能**局部**优化（~3-5 Å 范围）
3. 参数文件错误的配体会出问题
4. 极端低 pH / 高温环境无法模拟

**最佳实践**：relax 前先用 AlphaFold / 实验结构 + 手工清洗。

## 4. cartesian_ddg.linuxgccrelease 详解

### 4.1 工具定位

| 项目 | 内容 |
|---|---|
| **类型** | C++ 编译二进制 |
| **位置** | `$ROSETTA_BIN/cartesian_ddg.linuxgccrelease` |
| **用途** | Cartesian 空间 ΔΔG 计算 |
| **核心算法** | 突变 + 局部弛豫 + 能量评估 |
| **本项目用法** | 饱和突变扫描 |

### 4.2 ΔΔG 是什么

**ΔΔG** = 突变后与突变前的自由能差：

```
ΔΔG = ΔG(mutant) - ΔG(wildtype)
```

| 范围 | 含义 |
|---|---|
| ΔΔG < -1 REU | 突变后**更稳定**（亲和力可能提高） |
| ΔΔG > 1 REU | 突变后**不稳定**（亲和力可能降低） |
| -1 ≤ ΔΔG ≤ 1 | 中性突变 |

**单位 REU（Rosetta Energy Unit）** ≠ kcal/mol，但相关性强（Pearson r ≈ 0.9）。

### 4.3 Cartesian DDG vs DDG Monomer

| 工具 | 用途 |
|---|---|
| `cartesian_ddg` | **Cartesian 空间**，本项目用 |
| `ddg_monomer` | Torsional 空间，单体稳定性 |

**Cartesian DDG 优势**：

- 对 loop 突变更友好
- 局部优化更精确
- 大多数场景推荐

### 4.4 工作原理

```
1. 输入：wt_relaxed.pdb（来自 Step 2 弛豫后）
2. 输入：mutations.txt（要计算的突变列表）
3. 对每个突变：
   a. 突变残基类型 + 优化侧链
   b. 局部 FastRelax（仅突变残基 ± 8 Å）
   c. 记录 ΔG(mutant)
4. 输出：每个突变的 ΔG
5. 计算 ΔΔG = ΔG(mutant) - ΔG(wildtype)
```

**关键参数**：

| 参数 | 含义 |
|---|---|
| `-s` | 输入 PDB |
| `-ddg:mut_file` | 突变文件 |
| `-ddg:iterations N` | 每个突变重复 N 次取平均 |
| `-ddg:cartesian` | **使用 Cartesian DDG** |
| `-ddg:bbnbrs 1` | 弛豫侧链时的邻居数 |
| `-score:weights ref2015_cart.wts` | 力场 |

### 4.5 mutations.txt 文件格式

```
<resnum> <chain> <wt_aa> <n_mutations>
```

**示例**（饱和扫描位点 71）：

```
71 A Q 19
```

**本项目对多位点生成多个 mutation 记录**：

```
71 A Q 19  # 71 位 Q → 19 种氨基酸
72 A I 19  # 72 位 I → 19 种氨基酸
```

**位置编号**：是 **Rosetta 内部绝对行号**（不是 PDB 编号）！

### 4.6 编号映射（重点！）

⚠️ **本项目最重要的"编号铁律"**：

| 维度 | 编号体系 |
|---|---|
| **PDB 文件** | 链 + 残基号（如 `A:71`） |
| **Rosetta 内部** | 绝对行号（从 1 开始数所有 CA 原子） |

**唯一转换函数**：[rosetta_tools.py `_build_rosetta_numbering`](../../详解rosetta-agent/04-核心代码详解.md)

```python
def _build_rosetta_numbering(pdb_path: str):
    """扫描 PDB 中所有 CA 原子，构建双向编号映射"""
    rosetta_to_pdb = {}      # {rosetta_idx: "chain_resnum"}
    pdb_to_rosetta = {}      # {"chain_resnum": rosetta_idx}
    wt_aa_dict = {}          # {rosetta_idx: "Q"}

    rosetta_idx = 1
    with open(pdb_path, 'r') as f:
        for line in f:
            if line.startswith("ATOM") and line[12:16].strip() == "CA":
                chain = line[21].strip()
                resnum = int(line[22:26].strip())
                resname = line[17:20].strip()

                wt_aa = _AA_3TO1[resname]

                rosetta_to_pdb[rosetta_idx] = f"{chain}_{resnum}"
                pdb_to_rosetta[f"{chain}_{resnum}"] = rosetta_idx
                wt_aa_dict[rosetta_idx] = wt_aa

                rosetta_idx += 1

    return rosetta_to_pdb, pdb_to_rosetta, wt_aa_dict
```

**调用方式**：

```python
rosetta_to_pdb, pdb_to_rosetta, wt_aa_dict = _build_rosetta_numbering(pdb_path)

# 用户输入 PDB 编号 "71"
rosetta_idx = pdb_to_rosetta["A_71"]   # 假设是 73
# 用 rosetta_idx = 73 写进 mutations.txt
```

### 4.9 在本项目中的并发实现

```python
@tool
def run_saturation_mutagenesis(target_resnum: str, jobs: int = 10, delay: float = 1.5) -> str:
    """调 cartesian_ddg 跑饱和突变扫描"""
    workspace = get_workspace_path("saturation_mutagenesis")
    wt_relaxed = os.path.join(workspace, "../cartesian_relax/wt_relaxed.pdb")

    # 1. 解析 target_resnum（如 "71,72" 或 "A_71,A_72"）
    sites = _parse_mutation_sites(target_resnum)

    # 2. 编号映射：PDB 编号 → Rosetta 编号
    rosetta_to_pdb, pdb_to_rosetta, wt_aa_dict = _build_rosetta_numbering(wt_relaxed)

    # 3. 生成 mutations.txt
    mutations = []
    for site in sites:
        rosetta_idx = pdb_to_rosetta[site]
        wt_aa = wt_aa_dict[rosetta_idx]
        mutations.append((rosetta_idx, wt_aa, 19))   # 19 = 19 种氨基酸

    # 4. 写 mutations.txt
    with open(os.path.join(workspace, "mutations.txt"), "w") as f:
        for rosetta_idx, wt_aa, n in mutations:
            f.write(f"{rosetta_idx} A {wt_aa} {n}\n")   # 假设单链

    # 5. 生成运行脚本（含 ThreadPoolExecutor + 错峰）
    script = f"""
import subprocess, time
from concurrent.futures import ThreadPoolExecutor

def execute(task):
    resnum, wt_aa, target_aa = task
    cmd = f"$ROSETTA_BIN/cartesian_ddg.linuxgccrelease \\
        -s wt_relaxed.pdb \\
        -ddg:mut_file mutations_subset.txt \\
        -ddg:iterations 3 \\
        -ddg:cartesian \\
        -score:weights ref2015_cart.wts \\
        -out:prefix mut_{resnum}_{target_aa}_"
    subprocess.run(cmd, shell=True, capture_output=True)

tasks = [...]
with ThreadPoolExecutor(max_workers={jobs}) as pool:
    for task in tasks:
        pool.submit(execute, task)
        time.sleep({delay})  # 错峰延迟
"""

    # 6. 后台执行（不等完成）
    subprocess.Popen(["python", "run_ddg.py"], cwd=workspace)
    return "✅ 饱和突变任务已提交后台执行，进度通过 progress_poll 节点轮询"
```

### 4.12 cartesian_ddg 准确度

| 任务 | 与实验相关性 |
|---|---|
| 蛋白稳定性 ΔG | Pearson r ≈ 0.7 |
| 结合亲和力 ΔΔG_bind | Pearson r ≈ 0.5-0.6 |
| 抗原-抗体 | Pearson r ≈ 0.5 |

**典型误差**：

- |ΔΔG| < 1 REU：不可信
- 1 ≤ |ΔΔG| ≤ 3 REU：方向可能对，绝对值偏差大
- |ΔΔG| > 3 REU：基本可信

**典型陷阱**：

- 大构象变化突变（突变后结构差异大）不准
- 高电荷残基（R、K、E、D）替换不准
- 脯氨酸突变（需要 backbone 调整）特殊

### 4.13 关键 flag 详解

| Flag | 含义 | 本项目设置 |
|---|---|---|
| `-ddg:iterations` | 每个突变重复次数 | 3 |
| `-ddg:bbnbrs` | 侧链 packing 半径（残基数） | 1 |
| `-ddg:bb_move` | 是否移动 backbone | false |
| `-ddg:cartesian` | 用 Cartesian 弛豫 | **true** |
| `-ddg:min_cst` | 加约束 | false |
| `-ddg:fast` | 快速模式（不推荐） | false |
| `-ddg:sc_avg_only_if_match` | 仅匹配时平均 | false |

### 4.14 性能优化

| 优化 | 加速比 |
|---|---|
| jobs=48 + delay=1.5（HPC） | 30-40x |
| iterations=3 vs 1 | 3x（精读也 3x） |
| bbnbrs=1 vs 0 | 1.5x |
| cartesian vs torsional | 0.5x（Cartesian 慢 2x） |

**768 核 HPC 上**：

- 单突变：~5 分钟
- 19 突变饱和扫描：~1.5 小时（jobs=48）
- 5 位点 × 19 突变 = 95 个：~8 小时

## 6. 工具的局限与未来改进

### 6.1 当前局限

| 局限 | 影响 |
|---|---|
| 单体 ΔΔG 不能直接预测亲和力变化 | 蛋白-蛋白需要额外对接 |
| 配体必须预处理好（mol2 + CONECT） | 上游处理负担 |
| 大构象变化突变不准 | 限制应用场景 |
| 没有考虑动力学效应 | 只算平衡态 |

### 6.2 未来改进

1. **ML 混合**：用 ProteinMPNN / ESM-2 预排序突变，再跑 cartesian_ddg
2. **跨蛋白 ΔΔG**：集成 interface_ddg
3. **MD 后处理**：把 ddg_results 作为 MD 模拟的初始结构
4. **批量 ML 预测**：用 AlphaFold-Multimer 预测突变体结构

## 7. 一句话总结

**本项目用 Rosetta 的 `molfile_to_params.py` 做配体参数化、`relax.linuxgccrelease -relax:cartesian` 做结构弛豫、`cartesian_ddg.linuxgccrelease` 做饱和突变 ΔΔG 扫描——三个工具组合实现了从复合物结构清洗到高通量突变评估的完整流水线，是整个 Rosetta-Agent 项目的科学计算基石。**
