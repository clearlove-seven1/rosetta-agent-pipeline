```

│   │   ├── basic/          # 基础工具

│   │   ├── ObjexxFCL/      # Fortran 兼容库
│   │   └── apps/           # 命令行应用程序
│   ├── cmake/              # CMake 构建脚本
│   └── scripts/python/public/  # 公开 Python 脚本

```

### 1.2 关键 C++ 类

**Pose（核心数据结构）**：

```cpp
class Pose {
    // 当前构象
    conformation::Conformation conformation_;
    // 序列信息
    sequence::SequenceCOP sequence_;
    // 能量分解
    energies::EnergiesCache energies_;
    // 数据缓存
    cached_energies::CachedEnergiesBigMean big_energies_;
    // ... 几十个成员
};
```

`Pose` 是 Rosetta 的核心，**一个 Pose = 一个蛋白结构 + 序列 + 能量状态**。所有操作都围绕 Pose。

**ScoreFunction（能量函数）**：

```cpp
class ScoreFunction {
    // 权重表
    ScoreTypeWeights weights_;
    // 各项能量计算器
    EnergyMethodMap methods_;
    // 评分
    Real score(Pose & pose);
};
```

**Mover（动作）**：

```cpp
class Mover {
    virtual void apply(Pose & pose) = 0;
    virtual std::string get_name() const = 0;
};
```

`Mover` 是 Rosetta 的"动作"抽象。任何改变 Pose 的操作都是 Mover（如 `MutateResidue`、`FastRelax`、`SmallMover` 等）。

**Filter（过滤器）**：

```cpp
class Filter {
    virtual bool apply(Pose & pose) const = 0;
    virtual Real report_sm(Pose & pose) const = 0;
};
```

`Filter` 评估 Pose 的某些性质（能量、距离、接触数），决定是否接受。

**Packer（侧链构象搜索）**：

```cpp
class Packer {
    // 侧链 rotamer 组合搜索
    // 找出能量最低的 rotamer 组合
};
```

## 2. Pose 数据结构详解

### 2.1 内部表示

Rosetta 用**全原子**模型（与 GROMACS 的粗粒度模型不同）：

```
Pose
├── residues: [Residue1, Residue2, ...]   # 每个残基
│   ├── atoms: [Atom1, Atom2, ...]         # 每个原子
│   │   ├── xyz: (x, y, z)                # 坐标
│   │   ├── id: atom_type_id
│   │   └── ...
│   ├── name: "ALA" | "GLY" | ...
│   ├── chain: 1
│   └── seqpos: 1
├── conformation:
│   ├── torsion: [φ, ψ, ω, χ1, χ2, ...]   # 二面角
│   └── ...
└── energies:
    ├── fa_atr: 范德华吸引
    ├── fa_rep: 范德华排斥
    └── ...
```

### 2.2 坐标 vs 二面角

Rosetta **既存全原子坐标，又存二面角**（内部坐标表示）：

- **修改结构**：通常改二面角（如 χ1、φ、ψ）
- **输出 PDB**：根据二面角 + 模板坐标生成全原子坐标
- **弛豫**：在 Cartesian 空间直接调坐标（ref2015_cart）

两种表示的转换：

```
        二面角 (φ, ψ, χ1, ...)
            ↓ 计算
        全原子坐标 (x, y, z)
            ↓ 计算
        能量（距离相关）
```

### 2.3 残基类型系统

每个 Residue 是一个**实例**，由 ResidueType 定义：

```cpp
class ResidueType {
    std::string name3_;          // "ALA", "GLY", ...
    AA aa_;                      // enum (aa_ala, aa_gly, ...)
    std::vector<AtomType> atom_types_;
    std::vector<Bond> bonds_;
    // ...
};

// 20 种标准氨基酸 + 修饰氨基酸 + 配体
```

## 3. 能量函数（Force Field）

### 3.1 能量函数的组成

Rosetta 能量函数是**多分量加权求和**：

```
E_total = w_1 * E_1 + w_2 * E_2 + ... + w_n * E_n
```

各项 E_i 是不同物理/统计势能，权重 w_i 通过训练数据调整。

### 3.2 标准力场 ref2015

**ref2015**（Alford et al. 2017）是当前最常用的力场，包含约 20 项：

| 项 | 含义 | 单位 |
|---|---|---|
| `fa_atr` | 全原子范德华吸引（Lennard-Jones 吸引项） | REU |
| `fa_rep` | 全原子范德华排斥（Lennard-Jones 排斥项） | REU |
| `fa_sol` | Lazaridis-Karplus 隐式溶剂（溶剂化） | REU |
| `fa_intra_rep` | 同残基内范德华排斥 | REU |
| `fa_intra_sol_xover4` | 同残基内溶剂化（残基内） | REU |
| `lk_ball_wtd` | 隐式水模型原子 ball 权重 | REU |
| `fa_elec` | 库仑静电 | REU |
| `pro_close` | 脯氨酸闭合项 | REU |
| `hbond_sr_bb` | 短程 backbone-backbone 氢键 | REU |
| `hbond_lr_bb` | 长程 backbone-backbone 氢键 | REU |
| `hbond_bb_sc` | backbone-sidechain 氢键 | REU |
| `hbond_sc` | sidechain-sidechain 氢键 | REU |
| `dslf_fa13` | Disulfide 键几何（Faure 2013） | REU |
| `rama` | Ramachandran 二面角偏好 | REU |
| `omega` | 反式肽键偏好 | REU |
| `p_aa_pp` | 氨基酸类型依赖的 backbone 偏好 | REU |
| `yhh_planarity` | 酪氨酸羟基平面性 | REU |
| `chi` | 侧链 rotamer 偏好 | REU |
| `ref` | 参考能量 | REU |

**单位 REU（Rosetta Energy Unit）**：不是 kcal/mol，数值近似但不同。

### 3.3 ref2015_cart 变体

**Cartesian 空间力场**，主要用于：

- Cartesian 弛豫
- cartesian_ddg（本项目用）

加入额外的 Cartesian 约束项：

| 项 | 含义 |
|---|---|
| `cart_bonded` | 键长/键角/二面角偏差惩罚 |
| `pro_close` | 脯氨酸环闭合 |

Cartesian 弛豫直接调原子坐标（不像 torsional 调二面角），**对 loop 和无序区更友好**。

### 3.4 力场的发展史

| 力场 | 年份 | 关键改进 |
|---|---|---|
| `score12` | ~2008 | 经典 |
| `talaris2013` | 2013 | 重新拟合权重 |
| `talaris2014` | 2014 | 修订 |
| `ref2015` | 2017 | **当前标准** |
| `ref2015_cart` | 2017 | Cartesian 空间 |
| `gen_potential` | 2020+ | ML 增强（试验） |

### 3.5 力场权重的学习

ref2015 权重通过**最大似然拟合**得到：

1. 准备训练集：~10000 个实验结构
2. 每个残基位点做饱和突变 → 算 ΔΔG_predicted
3. 与实验 ΔΔG 比较
4. 调整权重使 RMSE 最小化

这是 Rosetta 与分子动力学不同之处——**能量函数是数据驱动的**，不是纯物理。

### 3.6 统计势能 vs 物理势能

Rosetta 能量函数是**混合**的：

| 物理势能 | 统计势能 |
|---|---|
| 范德华（fa_atr/fa_rep） | Ramachandran 偏好（rama） |
| 库仑（fa_elec） | 侧链 rotamer 偏好（chi） |
| 氢键（hbond_*） | 参考能量（ref） |
| 隐式溶剂（fa_sol） | Disulfide 偏好（dslf_fa13） |
| 键几何（cart_bonded） | |

**统计势能优势**：补偿物理势能的偏差，从进化数据中学到经验规律。
**统计势能劣势**：可能过拟合训练集分布，对新颖蛋白不准。

## 4. 采样器（Mover）

Rosetta 用**蒙特卡洛 + 模拟退火**采样，Mover 实现各种 move：

### 4.1 Backbone Mover

| Mover | 修改 |
|---|---|
| `SmallMover` | 随机小角度扰动 φ/ψ |
| `ShearMover` | 平行剪切（保持二级结构） |
| `WobbleMover` | C 端小扰动 |
| `BackboneTweakMover` | 单残基小扰动 |
| `BBGaussMover` | 高斯扰动 |
| `KinkMover` | 引入 kink |
| `HelixJumpMover` | 改变螺旋相位 |

### 4.2 Sidechain Mover

| Mover | 修改 |
|---|---|
| `RotamerTrialsMover` | 随机尝试侧链 rotamer |
| `PackRotamersMover` | 完整侧链 packing |
| `MinMover` | 能量最小化 |
| `MutateResidue` | 突变残基类型 |

### 4.3 Specialized Mover

| Mover | 修改 |
|---|---|
| `RigidBodyMover` | 刚体平移/旋转 |
| `LoopMover` | Loop 区域特殊处理 |
| `CartesianPerturbMover` | Cartesian 坐标扰动 |
| `FragmentMover` | 插入片段 |

## 5. 优化流程

Rosetta 的**核心优化循环**：

```
当前 Pose
   │
   ▼
MonteCarloMetropolis
   │
   ├─ propose move (Mover)
   │
   ├─ score new Pose (ScoreFunction)
   │
   ├─ accept with probability min(1, exp(-ΔE/kT))
   │
   ▼
更新 Pose
   │
   ▼
退火降温（temperature 降低）
   │
   ▼
重复
```

### 5.1 模拟退火（Annealing）

```python
# PyRosetta 伪代码
from pyrosetta import *
init()

sf = get_score_function()  # ref2015

# 退火
kT = 1.0
while kT > 0.1:
    mover.apply(pose)
    new_score = sf(pose)
    if new_score < old_score:
        accept()
    elif random() < exp((old_score - new_score) / kT):
        accept()
    kT *= 0.99
```

### 5.2 FastRelax 协议

**FastRelax** 是 Rosetta 最常用的弛豫协议（**本项目用 relax.linuxgccrelease -relax:cartesian -score:weights ref2015_cart**）：

```cpp
// FastRelax 算法
1. 全原子 MinMover（Cartesian 最小化）
2. RotamerTrials + Min（侧链优化）
3. 重复 5-15 次（ref2015 默认 5 次）
4. 模拟退火（温度从高到低）
5. 最终能量最小化
```

**典型能量降低**：输入结构平均能量 -200 REU，FastRelax 后 -350 REU（值越小越好）。

## 6. 任务执行方式

### 6.1 命令行模式

```bash
relax.linuxgccrelease \
    -s input.pdb \
    -relax:cartesian \
    -score:weights ref2015_cart \
    -nstruct 3 \
    -out:prefix S1_
```

**关键 flags**：
- `-s`：输入 PDB
- `-relax:cartesian`：使用 Cartesian 弛豫
- `-score:weights`：指定力场
- `-nstruct`：独立运行次数（取最低能量）
- `-out:prefix`：输出文件前缀

### 6.2 RosettaScripts 模式（XML）

```bash
rosetta_scripts.linuxgccrelease \
    -parser:protocol protocol.xml \
    -s input.pdb \
    -score:weights ref2015.wts
```

### 6.3 PyRosetta 模式

```python
from pyrosetta import *
init()
pose = pose_from_pdb("input.pdb")
sf = get_score_function()
fastrelax = pyrosetta.rosetta.protocols.relax.FastRelax()
fastrelax.apply(pose)
pose.dump_pdb("output.pdb")
```

## 9. 与 ML 工具的对比

| 维度 | Rosetta | AlphaFold / ESM-2 / RFdiffusion |
|---|---|---|
| 范式 | 蒙特卡洛 + 物理+统计能量 | 深度学习 |
| 训练数据 | 实验结构 + 统计 | 序列 + 结构数据 |
| 物理真实性 | 中（统计势能补偿） | 低（黑盒） |
| 可解释性 | 高（每个能量项都有意义） | 低 |
| 设计能力 | **极强**（物理约束） | 中（需要后处理） |
| 预测速度 | 慢（采样） | **极快** |
| 适用场景 | 设计、ΔΔG、对接 | 预测、初始设计 |
| 代表任务 | ΔΔG 预测、酶设计 | 结构预测、序列生成 |

**结论**：本项目（Rosetta-Agent）用 Rosetta 做 **ΔΔG 预测**——这是 ML 工具**做不到或精度差**的任务。ESM-2 过滤 + Rosetta 计算 = 取长补短。
